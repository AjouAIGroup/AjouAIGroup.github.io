Cloudflare 계정

가입 후 이메일 확인과 2단계 인증을 먼저 합니다

Cloudflare 계정은 사이트, Workers, API Token의 권한 경계입니다. 개인 계정 하나를 여러 고객 사이트에 공유하기보다 운영 조직 또는 고객별 계정을 분리하는 편이 안전합니다.

1

Cloudflare 계정을 만듭니다

Cloudflare Sign up에서 이메일과 비밀번호를 입력해 계정을 만듭니다. 팀 운영이라면 개인 이메일보다 운영용 별칭 또는 메일링 리스트를 계정 복구용 연락처로 두는 방식을 권장합니다.

2

이메일을 확인합니다

Cloudflare가 보낸 확인 메일의 링크를 엽니다. 메일을 찾지 못하면 스팸함을 확인하고, 대시보드의 My Profile에서 확인 메일을 다시 보낼 수 있습니다.

3

2단계 인증을 켭니다

대시보드에서 다음 경로로 이동합니다.

My ProfileAuthenticationMobile App 또는 Security Key

복구 코드도 비밀번호 관리자에 보관합니다. Cloudflare는 계정 보안을 위해 2단계 인증 사용을 권장합니다.

4

운영 계정을 선택합니다

여러 사이트를 한 조직이 운영한다면 하나의 Cloudflare Account 안에 사이트를 둘 수 있습니다. 고객 또는 조직이 다른 경우에는 계정을 분리하고 해당 계정에 운영자를 멤버로 초대하는 편이 토큰 회수와 비용 정산에 유리합니다.

참고

계정 생성 시 Cloudflare는 이메일 확인 메일을 보내며, 계정명은 이후 설정 화면에서 변경할 수 있습니다. 최신 절차는 Cloudflare 계정 생성 안내를 기준으로 확인합니다.

Web Analytics 사이트를 등록하고 비콘을 설치합니다

GitHub Pages처럼 Cloudflare 프록시를 거치지 않는 사이트는 JavaScript 스니펫을 직접 추가합니다. Cloudflare가 프록시하는 도메인과 Cloudflare Pages는 더 간단한 자동 설정도 가능합니다.

1

Web Analytics에서 사이트를 추가합니다

Analytics & LogsWeb AnalyticsAdd a site

hostname만 입력합니다. 예를 들어 example.org 또는 team.github.io처럼 입력합니다. https://, /admin, /news 같은 경로는 넣지 않습니다.

2

사이트 유형에 맞는 설치 방식을 고릅니다

  • GitHub Pages, Vercel, Netlify, 자체 서버: Manage site에서 받은 스니펫을 직접 설치합니다.
  • Cloudflare 프록시 도메인: Add a site에서 hostname을 고르면 자동 삽입을 사용할 수 있습니다.
  • Cloudflare Pages: Workers & Pages의 프로젝트에서 Metrics를 열고 Web Analytics를 Enable할 수 있습니다.
3

비콘 토큰을 기록합니다

Manage site에 표시되는 스니펫은 다음 형태입니다. 여기서 token 문자열만 복사해 둡니다. 이 값은 site_token이며 공개 홈페이지에 포함될 수 있는 사이트 식별자입니다.

Cloudflare가 제공하는 비콘 스니펫 
<script
  defer
  src="https://static.cloudflareinsights.com/beacon.min.js"
  data-cf-beacon='{"token":"SITE_TOKEN"}'>
</script>

실제 스니펫의 SITE_TOKEN 자리에 Cloudflare가 발급한 값이 들어 있습니다.

4

정적 HTML 사이트는 body 끝에 스니펫을 넣습니다

직접 HTML을 관리한다면 모든 페이지의 </body> 바로 앞에 Cloudflare가 발급한 스니펫을 넣습니다. 배포 후 실제 사이트에서 한 번 이상 페이지를 열어야 데이터가 생성됩니다.

Vite와 React에서 비콘을 한 번만 추가하는 예시

SPA에서는 경로 이동마다 스크립트를 제거하고 다시 넣지 않는 것이 중요합니다. 아래 컴포넌트는 최초 로드 시 한 번만 비콘을 삽입합니다.

src/components/CloudflareAnalytics.jsx 
import { useEffect } from "react";

const BEACON_ID = "cloudflare-web-analytics";

export default function CloudflareAnalytics() {
    const token = import.meta.env.VITE_CLOUDFLARE_WEB_ANALYTICS_TOKEN;

    useEffect(() => {
        if (!token || window.location.pathname.startsWith("/admin")) {
            return undefined;
        }

        if (document.getElementById(BEACON_ID)) {
            return undefined;
        }

        const script = document.createElement("script");
        script.id = BEACON_ID;
        script.defer = true;
        script.src = "https://static.cloudflareinsights.com/beacon.min.js";
        script.dataset.cfBeacon = JSON.stringify({ token, spa: false });
        document.body.append(script);
    }, [token]);

    return null;
}

앱의 최상위 컴포넌트에서 <CloudflareAnalytics />를 한 번만 렌더링합니다. spa: false는 클라이언트 경로 이동을 추가 페이지뷰로 기록하지 않아 공개 페이지에서 관리자 경로로 이동해도 관리자 페이지뷰가 남지 않게 합니다. 관리자 경로도 측정하려면 window.location.pathname.startsWith("/admin") 조건을 제거하고 SPA 정책을 별도로 결정합니다.

데이터 반영

Cloudflare 공식 안내에 따라 비콘 설치 직후에는 데이터가 나타나기까지 몇 분이 걸릴 수 있습니다. 설치 후 실제 공개 사이트를 열고 Web Analytics 화면에서 확인합니다.

관리자 API에 필요한 값

Account ID, site_tag, API Token을 준비합니다

이 단계부터는 대시보드 통계를 외부 관리자 화면에서 조회할 때만 필요합니다. 핵심은 site_token과 site_tag가 다른 값이라는 점입니다.

1

Cloudflare Account ID를 복사합니다

Cloudflare 대시보드에서 Command + K 또는 Ctrl + K를 눌러 Copy account ID를 검색합니다. 또는 Workers & Pages의 Account details에서 확인할 수 있습니다. Zone ID가 아니라 Account ID를 사용합니다.

2

읽기 전용 API Token을 만듭니다

사용자 API Token 생성 경로입니다.

My ProfileAPI TokensCreate TokenCreate Custom Token

토큰 이름은 다음처럼 용도를 명확히 지정합니다.

권장 토큰 이름과 권한 
Name: Website Analytics Read

Permissions:
Account - Account Analytics - Read
Account - Account Settings - Read

Account Resources:
Include - Specific account - 대상 Cloudflare Account

Account Analytics Read는 GraphQL 통계 조회용입니다. Account Settings Read는 Web Analytics 사이트 목록 API를 통해 site_tag를 찾을 때 필요합니다. 둘 다 읽기 전용입니다.

특정 사용자의 퇴사나 권한 변경에 영향을 받지 않는 장기 연동이 필요하고 Super Administrator 권한이 있다면, Manage Account의 API Tokens에서 Account-owned token을 만드는 방법도 고려합니다. 여러 조직이나 고객을 운영할 때는 사이트 또는 고객 계정 단위로 토큰을 분리하는 편이 안전합니다.

가장 엄격한 최소 권한 구성을 원한다면 site_tag를 확인할 때만 Account Settings Read가 있는 임시 토큰을 사용하고, 운영 Worker에는 Account Analytics Read만 가진 별도 토큰을 등록합니다.

토큰은 생성 직후 한 번만 표시될 수 있습니다. 즉시 비밀번호 관리자에 저장하고 채팅이나 Git에 올리지 않습니다.

3

토큰 상태를 확인합니다

토큰을 화면이나 셸 기록에 남기지 않도록 숨김 입력으로 받습니다.

macOS, Linux 
read -s SITE_CF_API_TOKEN
printf 'Authorization: Bearer %s\n' "$SITE_CF_API_TOKEN" | \
  curl --silent --show-error \
    "https://api.cloudflare.com/client/v4/user/tokens/verify" \
    --header @-
unset SITE_CF_API_TOKEN

success: true와 status: active가 나오면 유효합니다.

4

RUM 사이트 목록에서 site_tag를 확인합니다

아래 명령에서 첫 번째 입력에는 API Token, 두 번째 입력에는 Account ID를 넣습니다. 값은 출력되지 않습니다.

site_tag와 site_token 확인 
read -s SITE_CF_API_TOKEN
read -r SITE_CF_ACCOUNT_ID
printf 'Authorization: Bearer %s\n' "$SITE_CF_API_TOKEN" | \
  curl --silent --show-error \
    "https://api.cloudflare.com/client/v4/accounts/${SITE_CF_ACCOUNT_ID}/rum/site_info/list" \
    --header @-
unset SITE_CF_API_TOKEN
unset SITE_CF_ACCOUNT_ID

응답의 host가 대상 사이트와 같은 객체를 찾습니다. 그 객체의 site_tag는 Worker Secret에, site_token은 프런트엔드 빌드 변수에 사용합니다.

Authentication error

사이트 목록 요청에서 Cloudflare 오류 코드 10000이 나오면 먼저 토큰이 실제로 입력됐는지 확인하고, Account Settings Read 권한을 추가합니다. 이 목록 API는 Analytics Read만으로는 호출할 수 없습니다.

Worker를 배포하고 Secret을 입력합니다

Worker는 브라우저와 Cloudflare GraphQL API 사이의 보호막입니다. API Token을 프런트엔드에 넣지 않고, 허용된 홈페이지 origin과 관리자 접근 키를 확인한 뒤 집계 데이터만 반환합니다.

1

Worker 프로젝트 폴더를 만듭니다

기존 저장소 안에 전용 폴더를 만듭니다. 아래는 예시 경로이며, 실제 프로젝트 이름으로 바꿔도 됩니다.

프로젝트 구조 
cloudflare/
  analytics-admin-api/
    worker.js
    wrangler.toml
2

wrangler.toml을 작성합니다

ADMIN_ORIGIN에는 관리자 화면을 제공하는 공개 홈페이지의 origin만 입력합니다. protocol을 포함하고, 마지막 slash와 path는 넣지 않습니다.

cloudflare/analytics-admin-api/wrangler.toml 
name = "website-analytics-admin-api"
main = "worker.js"
compatibility_date = "2026-09-08"

[vars]
ADMIN_ORIGIN = "https://www.example.org"

[[ratelimits]]
name = "ADMIN_RATE_LIMITER"
namespace_id = "1001"

[ratelimits.simple]
limit = 10
period = 60

[env.dev.vars]
ADMIN_ORIGIN = "https://www.example.org,http://localhost:5173"

[[env.dev.ratelimits]]
name = "ADMIN_RATE_LIMITER"
namespace_id = "1002"

[env.dev.ratelimits.simple]
limit = 10
period = 60

[env.dev.vars]는 로컬 개발 전용입니다. 운영 배포에는 top-level [vars]만 사용합니다.

3

Worker 코드를 작성합니다

아래 코드는 7일과 30일 조회, 페이지별 통계, 유입 경로, 기기, 국가, CORS, 접근 키, 상태 점검을 포함한 완전한 최소 구현입니다.

worker.js 전체 코드 열기
cloudflare/analytics-admin-api/worker.js 
const CLOUDFLARE_GRAPHQL_ENDPOINT =
    "https://api.cloudflare.com/client/v4/graphql";
const ALLOWED_PERIODS = new Set([7, 30]);

const getAllowedOrigins = (env) =>
    String(env.ADMIN_ORIGIN || "")
        .split(",")
        .map((origin) => origin.trim())
        .filter(Boolean);

const getAllowedOrigin = (request, env) => {
    const origin = request.headers.get("Origin") || "";
    return getAllowedOrigins(env).includes(origin) ? origin : "";
};

const json = (request, env, body, status = 200) => {
    const headers = {
        "Access-Control-Allow-Headers": "Authorization, Content-Type",
        "Access-Control-Max-Age": "86400",
        "Access-Control-Allow-Methods": "GET, OPTIONS",
        "Cache-Control": "no-store",
        "Content-Type": "application/json; charset=utf-8",
        Vary: "Origin",
    };
    const allowedOrigin = getAllowedOrigin(request, env);
    if (allowedOrigin) {
        headers["Access-Control-Allow-Origin"] = allowedOrigin;
    }

    return new Response(status === 204 ? null : JSON.stringify(body), {
        status,
        headers,
    });
};

const isAllowedOrigin = (request, env) => {
    const origin = request.headers.get("Origin");
    return !origin || getAllowedOrigins(env).includes(origin);
};

const isAuthorized = (request, env) => {
    const expected = String(env.ADMIN_TOKEN || "");
    const received = request.headers.get("Authorization") || "";
    if (!expected) return false;

    const encoder = new TextEncoder();
    const expectedBytes = encoder.encode(`Bearer ${expected}`);
    const receivedBytes = encoder.encode(received);
    return (
        expectedBytes.byteLength === receivedBytes.byteLength &&
        crypto.subtle.timingSafeEqual(expectedBytes, receivedBytes)
    );
};

const getAuthFailure = async (request, env, pathname) => {
    if (isAuthorized(request, env)) return null;

    if (env.ADMIN_RATE_LIMITER) {
        const clientAddress =
            request.headers.get("CF-Connecting-IP") || "unknown";
        try {
            const { success } = await env.ADMIN_RATE_LIMITER.limit({
                key: `${pathname}:${clientAddress}`,
            });
            if (!success) {
                return json(
                    request,
                    env,
                    { error: "관리자 접근 시도가 너무 많습니다." },
                    429,
                );
            }
        } catch {
            return json(
                request,
                env,
                { error: "관리자 접근 제한 서비스를 확인해주세요." },
                503,
            );
        }
    }

    return json(request, env, { error: "관리자 접근 키를 확인해주세요." }, 401);
};

const toIsoDate = (date) => date.toISOString().slice(0, 10);

const getDateRange = (days) => {
    const end = new Date();
    const start = new Date(end);
    start.setUTCDate(start.getUTCDate() - (days - 1));
    return { start: toIsoDate(start), end: toIsoDate(end) };
};

const createFilter = ({ start, end }, siteTag) =>
    `filter: { date_geq: ${JSON.stringify(start)}, date_leq: ${JSON.stringify(end)}, siteTag: ${JSON.stringify(siteTag)}, bot: 0, requestPath_neq: "/admin" }`;

const buildQuery = (env, range) => {
    const accountTag = JSON.stringify(env.CLOUDFLARE_ACCOUNT_ID);
    const filter = createFilter(range, env.CLOUDFLARE_SITE_TAG);

    return `{
        viewer {
            accounts(filter: { accountTag: ${accountTag} }) {
                total: rumPageloadEventsAdaptiveGroups(${filter}, limit: 1) {
                    count
                    sum { visits }
                }
                series: rumPageloadEventsAdaptiveGroups(${filter}, limit: 31, orderBy: [date_ASC]) {
                    count
                    sum { visits }
                    dimensions { date }
                }
                topPages: rumPageloadEventsAdaptiveGroups(${filter}, limit: 10, orderBy: [count_DESC]) {
                    count
                    sum { visits }
                    dimensions { requestPath }
                }
                referrers: rumPageloadEventsAdaptiveGroups(${filter}, limit: 10, orderBy: [count_DESC]) {
                    count
                    dimensions { refererHost }
                }
                devices: rumPageloadEventsAdaptiveGroups(${filter}, limit: 10, orderBy: [count_DESC]) {
                    count
                    dimensions { deviceType }
                }
                countries: rumPageloadEventsAdaptiveGroups(${filter}, limit: 10, orderBy: [count_DESC]) {
                    count
                    dimensions { countryName }
                }
            }
        }
    }`;
};

const mapRows = (rows, field) =>
    (rows || []).map((row) => ({
        label: row.dimensions?.[field] || "",
        pageViews: row.count || 0,
    }));

const loadAnalytics = async (env, days) => {
    const range = getDateRange(days);
    const response = await fetch(CLOUDFLARE_GRAPHQL_ENDPOINT, {
        method: "POST",
        headers: {
            Authorization: `Bearer ${env.CLOUDFLARE_API_TOKEN}`,
            "Content-Type": "application/json",
        },
        body: JSON.stringify({ query: buildQuery(env, range) }),
    });
    const payload = await response.json();

    if (!response.ok || payload.errors?.length) {
        const detail =
            payload.errors?.map((error) => error.message).join("; ") ||
            `Cloudflare API returned ${response.status}`;
        throw new Error(detail);
    }

    const result = payload.data?.viewer?.accounts?.[0];
    if (!result) {
        throw new Error("Cloudflare account data was not returned.");
    }

    const total = result.total?.[0] || {};
    return {
        range: { days, ...range },
        totals: {
            pageViews: total.count || 0,
            visits: total.sum?.visits || 0,
        },
        series: (result.series || []).map((row) => ({
            date: row.dimensions?.date || "",
            pageViews: row.count || 0,
            visits: row.sum?.visits || 0,
        })),
        topPages: (result.topPages || []).map((row) => ({
            path: row.dimensions?.requestPath || "/",
            pageViews: row.count || 0,
            visits: row.sum?.visits || 0,
        })),
        referrers: mapRows(result.referrers, "refererHost"),
        devices: mapRows(result.devices, "deviceType"),
        countries: mapRows(result.countries, "countryName"),
        generatedAt: new Date().toISOString(),
    };
};

const isConfigured = (env) =>
    Boolean(
        env.CLOUDFLARE_API_TOKEN &&
            env.CLOUDFLARE_ACCOUNT_ID &&
            env.CLOUDFLARE_SITE_TAG &&
            env.ADMIN_TOKEN &&
            env.ADMIN_ORIGIN,
    );

export default {
    async fetch(request, env) {
        if (!isAllowedOrigin(request, env)) {
            return json(request, env, { error: "허용되지 않은 요청입니다." }, 403);
        }

        if (request.method === "OPTIONS") {
            return json(request, env, {}, 204);
        }

        const url = new URL(request.url);
        if (request.method === "GET" && url.pathname === "/health") {
            return json(request, env, {
                ok: true,
                configured: isConfigured(env),
            });
        }

        if (request.method !== "GET" || url.pathname !== "/v1/analytics") {
            return json(request, env, { error: "요청 경로를 찾을 수 없습니다." }, 404);
        }

        if (!isConfigured(env)) {
            return json(request, env, { error: "Worker 환경변수 설정이 필요합니다." }, 503);
        }

        const authFailure = await getAuthFailure(request, env, url.pathname);
        if (authFailure) return authFailure;

        const requestedDays = Number(url.searchParams.get("days") || 30);
        const days = ALLOWED_PERIODS.has(requestedDays) ? requestedDays : 30;

        try {
            return json(request, env, await loadAnalytics(env, days));
        } catch (error) {
            return json(
                request,
                env,
                {
                    error: "Cloudflare 통계를 불러오지 못했습니다.",
                    detail: error.message,
                },
                502,
            );
        }
    },
};

문제 해결

오류 메시지별로 원인을 분리합니다

상태 코드와 오류 문구를 먼저 확인하면 토큰, CORS, Worker 설정, Web Analytics 수집 문제를 빠르게 구분할 수 있습니다.

Cloudflare 10000RUM 사이트 목록 요청이 Authentication error를 반환한다
  1. 토큰 검증 API가 success: true인지 확인합니다.
  2. RUM 목록 API에는 Account Settings Read 권한이 필요합니다.
  3. Account ID가 아닌 Zone ID를 URL에 넣지 않았는지 확인합니다.
  4. API Token을 복사할 때 공백이나 줄바꿈이 들어가지 않았는지 확인합니다.
401관리자 페이지 또는 curl이 접근 키 오류를 반환한다

Worker의 ADMIN_TOKEN과 입력한 값이 다릅니다. Worker Secret을 다시 등록하고, 브라우저의 기존 세션 키를 지운 뒤 다시 입력합니다. Cloudflare API Token을 관리자 접근 키로 입력하면 안 됩니다.

403브라우저 Console에 CORS 또는 허용되지 않은 요청 오류가 보인다

요청을 보낸 페이지의 origin과 ADMIN_ORIGIN이 정확히 일치해야 합니다. protocol, www 포함 여부, 포트가 모두 중요합니다. 운영 origin에 http://localhost:5173을 넣지 말고, 로컬 테스트는 [env.dev.vars]에서만 허용합니다.

502Worker가 Cloudflare 통계를 불러오지 못했다고 반환한다
  1. CLOUDFLARE_API_TOKEN에 Account Analytics Read가 있는지 확인합니다.
  2. CLOUDFLARE_ACCOUNT_ID가 대상 계정인지 확인합니다.
  3. CLOUDFLARE_SITE_TAG에 site_token을 잘못 넣지 않았는지 확인합니다.
  4. Web Analytics 비콘이 실제 사이트에서 로드됐고 데이터가 생길 시간을 기다렸는지 확인합니다.
503/health 응답은 ok인데 configured가 false이거나 API가 설정 오류를 반환한다

네 개 Secret 중 하나가 누락됐습니다. CLOUDFLARE_API_TOKEN, CLOUDFLARE_ACCOUNT_ID, CLOUDFLARE_SITE_TAG, ADMIN_TOKEN을 각각 다시 등록합니다.

관리자 화면 설정 필요배포된 웹사이트가 Worker URL을 모르고 있다

GitHub Variables의 VITE_ADMIN_API_URL이 비어 있거나, 변수를 등록한 뒤 홈페이지를 다시 빌드하지 않은 상태입니다. Variables 값을 확인하고 GitHub Actions의 배포 workflow를 다시 실행합니다.

통계가 0비콘은 설치했지만 Web Analytics에 방문 데이터가 보이지 않는다
  1. 실제 배포된 HTML에 beacon.min.js가 포함됐는지 Network 탭에서 확인합니다.
  2. 등록한 hostname과 실제 접속 hostname이 같은지 확인합니다.
  3. 광고 차단 확장 프로그램을 끈 일반 브라우저 창에서 테스트합니다.
  4. 첫 페이지 방문 후 몇 분 기다렸다가 Analytics 화면을 새로 고칩니다.
workers.dev subdomain unavailable첫 Worker 배포 때 subdomain 이름을 사용할 수 없다고 나온다

계정용 workers.dev subdomain은 전 세계에서 고유해야 합니다. 조직명, 서비스명, 지역 또는 운영 접미사를 조합해 다시 입력합니다. 예: example-org-ops-kr. Worker 이름도 영문, 숫자, 하이픈 규칙을 지켜야 합니다.

다른 사이트에 반복 적용하는 방법

사이트마다 Web Analytics 항목, site_tag, origin, 관리자 접근 키를 분리하면 한 사이트의 설정 오류나 키 유출이 다른 사이트로 번지는 범위를 줄일 수 있습니다.

권장 단위

사이트당 Worker 하나와 ADMIN_TOKEN 하나를 권장합니다. 사용량이 작아도 관리 단위가 분명해지고 CORS origin, API Token 교체, 접근 키 회수가 쉬워집니다.

  • lab-a-analytics-api
  • lab-b-analytics-api
  • conference-analytics-api

각 사이트에서 바꿀 값

아래 항목을 복사한 뒤 사이트별로 채웁니다. Cloudflare 계정이 같더라도 site_tag와 ADMIN_ORIGIN은 사이트마다 달라집니다.

항목 사이트 A 사이트 B
hostname example-a.org example-b.org
site_token 비콘용 공개값 비콘용 공개값
site_tag Worker Secret Worker Secret
ADMIN_ORIGIN https://example-a.org https://example-b.org
ADMIN_TOKEN 별도 생성 별도 생성
Worker URL 별도 배포 별도 배포
A

새 hostname으로 Web Analytics 사이트를 추가합니다

같은 Cloudflare Account를 사용해도 각 hostname은 별도의 Web Analytics 사이트로 등록합니다. 새 site_token과 site_tag를 기록합니다.

B

Worker 폴더를 복사하고 이름과 origin을 바꿉니다

wrangler.toml의 name과 ADMIN_ORIGIN을 대상 사이트 값으로 바꿉니다. 기존 Worker의 Secret을 재사용하지 말고 새 Worker에 새 Secret을 등록합니다.

C

사이트 저장소의 빌드 변수 두 개를 바꿉니다

대상 저장소의 VITE_CLOUDFLARE_WEB_ANALYTICS_TOKEN과 VITE_ADMIN_API_URL을 그 사이트의 값으로 등록하고 재배포합니다.

중앙화가 필요한 경우

많은 사이트를 한 Worker에서 다루는 것도 가능하지만, hostname별 site_tag와 origin을 서버 측 매핑으로 관리하고 요청 hostname을 엄격히 검증해야 합니다. 처음에는 사이트당 Worker 방식이 단순하고 안전합니다.

운영 기준

Secret은 Worker에, 접근 제어는 서버 측에 둡니다

비콘 token은 공개 사이트 식별자입니다. 반면 Cloudflare API Token은 계정 데이터를 읽을 권한이 있으므로 배포 코드와 브라우저에서 철저히 분리해야 합니다.

현재의 최소 보안

Worker의 CORS allowlist와 ADMIN_TOKEN으로 통계 API를 막습니다. 소수 운영자가 통계를 보는 초기 단계에 적합합니다.

  • ADMIN_TOKEN은 세션에만 저장
  • API Token은 Worker Secret에만 저장
  • 사이트별 origin을 정확히 제한

관리자별 권한이 필요할 때

Cloudflare Access를 Worker 앞에 두고 이메일 OTP 또는 Google, GitHub, 학교 SSO로 사용자별 인증을 적용합니다.

  • 공유 접근 키 회수 문제 감소
  • 관리자별 접근 허용과 차단 가능
  • 관리자 화면 자체를 인증 전 차단 가능
즉시 폐기해야 하는 경우

API Token이나 ADMIN_TOKEN이 커밋, 채팅, 이슈, 공개 스크린샷에 노출됐다면 "삭제"만 하지 말고 Cloudflare에서 토큰을 Roll 또는 재발급하고 Worker Secret을 새 값으로 교체합니다. 노출된 값은 비밀번호 관리자에서도 갱신합니다.

비용을 확인하는 기준

  • Web Analytics는 기본 방문 분석을 무료로 시작할 수 있습니다.
  • 관리자 Worker의 조회량이 적다면 Workers Free 한도 안에서 운영할 수 있습니다.
  • Workers Paid는 월 $5 구독부터 시작하며 포함 요청과 CPU 한도가 달라집니다.
  • 정확한 한도와 금액은 기능과 시점에 따라 바뀔 수 있으므로 배포 전 공식 가격표를 확인합니다.
개인정보와 정책

Web Analytics 도입 전에는 기관의 개인정보 처리방침, 쿠키 정책, 방문자 고지 의무를 검토합니다. 특히 분석 도구를 추가로 함께 사용하거나 사용자 식별 이벤트를 보내는 경우에는 법률 및 내부 정책 검토가 필요합니다.
